# paper/

Working LaTeX skeleton for the **joint-response** paper:

> Can an unpaired sliced-Wasserstein autoencoder, trained only on real CMS open
> data plus a theory prior, learn the detector response well enough that the same
> object is identifiable, transfers to the Upsilon family (never trained on), and
> inverts per event?

The old "Run D / Run E physics-cost Neural-OT upgrade" narrative is dropped (it
lives in git history only, together with the previous `main.tex`).

- `FRAMING.md`: the paper tone, the three research questions, the claim ladder, the
  PRD-readiness assessment, the open problems and the ordered plan. **Read this
  first.**
- `main.tex`: re-framed skeleton in a **single-column, Nature-style** layout
  (unnumbered bold headings, superscript numbered citations, Methods at the end,
  Data/Code availability, Acknowledgements, Author contributions, Competing
  interests). Sections: Introduction (with related work folded in), Results
  (in-domain closure, identification, Upsilon transfer, systematics budget,
  per-event unfolding), Discussion, Methods. Numbers marked `[measured]` are
  traceable to a run directory; `[TODO]` markers are still missing. Compiles with
  pdflatex + bibtex to **12 pages** today, with the eight figures listed below.
- Build order: `pdflatex main && bibtex main && pdflatex main && pdflatex main`.
- `references.bib`: starting bibliography; expand and deduplicate before submission.
- **Figures live in `PaperPlots/images/`** (created 2026-10-01). `main.tex` sets
  `\graphicspath{{../PaperPlots/images/}}`, so every figure is referenced by bare
  filename and the PDF is built from that single directory. Current inventory
  (all copied or generated from committed/retained artifacts):

  `python scripts_joint/plot_per_event_closure.py`; regenerate the paperstyle pairs

Compile:

```bash
pdflatex main.tex
bibtex main
pdflatex main.tex
pdflatex main.tex
```

Where the numbers come from: `docs/project_tree.md` section 8 maps every claim to a
run directory; `memory.md` sections 1-3 hold the measured tables;
`outputs/cms_Joint/scorecard/` holds the identification scorecard per arm.
