[verification comparison against the previous VM - artifact-measured, not hypothesis]
# The 22.04 build's number was 554.8 +- 3.237 pb, with MG5 3.7.3, gcc 11.4.0 and
# NNPDF23/247000. Three changes separated the two builds: MG5 version, compiler,
# and PDF. run_02 above isolates the PDF, so the attribution is measured:
#
#   this VM NNPDF31 (643.7+-4.012) vs this VM NNPDF23 (556.9+-3.425)
#     -> +86.8 pb, combined error 5.275 pb  =  16.5 sigma
#   this VM NNPDF23 (556.9+-3.425) vs 22.04 NNPDF23 (554.8+-3.237)
#     -> +2.1 pb, combined error 4.713 pb   =   0.4 sigma
#   this VM NNPDF31 (643.7+-4.012) vs 22.04 NNPDF23 (554.8+-3.237)
#     -> +88.9 pb, combined error 5.155 pb  =  17.2 sigma
#
# CONCLUSION, artifact-measured: **the PDF family change accounts for essentially
# the whole 17.2 sigma difference.** Holding the PDF fixed at 247000, this 24.04 /
# MG5 3.7.0 / gcc 13.3.0 build agrees with the 22.04 / MG5 3.7.3 / gcc 11.4.0 build
# to 0.4 sigma - statistically indistinguishable. So the MG5 downgrade 3.7.3->3.7.0
# and the compiler move 11.4->13.3 together produce no measurable shift at this
# sample size, and the previous VM's 554.8 pb was low for exactly one reason: it was
# using NNPDF2.3 where the original used NNPDF3.1.
# Nothing was tuned to make any of these numbers agree.
